# EquipmentManager

Учебный прототип веб-приложения для учёта промышленного оборудования и дальнейшего развития процессов обслуживания. Репозиторий также содержит документы лабораторных работ и концепции интерфейса.

## Стек

- C#, .NET 9 (`net9.0`), ASP.NET Core.
- Blazor Web App с интерактивным серверным режимом (Interactive Server).
- Razor-компоненты, CSS и Bootstrap.
- Nullable reference types включены. В веб-проекте дополнительных `PackageReference` нет; тестовый проект использует NuGet-зависимости xUnit и Microsoft.NET.Test.Sdk.

## Текущие возможности

- Страница `/equipment`: реестр с пятью начальными демонстрационными записями, добавлением, редактированием и удалением с подтверждением.
- Поиск при вводе по наименованию и инвентарному номеру без учёта регистра; пробелы по краям запроса удаляются.
- Проверка обязательных полей, допустимых состояний и уникальности инвентарного номера; отмена формы без сохранения.
- Страница `/faults`: регистрация неисправности, выбор оборудования, обработка по цепочке «Новая» → «В работе» → «Завершена» с обязательными работами и результатом.
- Страница `/maintenance-history`: одна связанная запись на завершённую заявку, фильтр по оборудованию, сортировка от новых записей к старым.
- Адаптивная оболочка и горизонтальная прокрутка широких таблиц внутри контейнеров.
- Тестовый проект `EquipmentManager.Tests`: последний зафиксированный прогон — 15 пройденных тестов.

Оборудование, заявки и история хранятся в памяти общего процесса приложения и теряются при его перезапуске. Авторизация и проверка ролей не подключены; учебные подписи не являются реальными правами. PostgreSQL, фильтры состояния/подразделения и сводные показатели остаются дальнейшим развитием. Текст главной страницы о заглушках заявок и истории пока устарел; рабочие разделы доступны через меню.

Вместо `package.json` для управления сборкой и зависимостями используются `.csproj` и NuGet, а `.sln` объединяет веб-приложение и тесты. `npm install` и `npm run dev` для текущего проекта не требуются.

## Локальный запуск

Необходим .NET SDK 9.x с ASP.NET Core Runtime 9.x либо совместимый SDK с установленной средой выполнения .NET 9. Для работы через IDE подойдёт Visual Studio с поддержкой .NET 9 и компонентами ASP.NET.

В каталоге проекта выполните:

```powershell
dotnet restore EquipmentManager.sln
dotnet build EquipmentManager.sln --no-restore
dotnet test EquipmentManager.sln --no-build --no-restore
dotnet run --project EquipmentManager.csproj --launch-profile http
```

Откройте [список оборудования](http://localhost:5156/equipment), [заявки](http://localhost:5156/faults) или [историю обслуживания](http://localhost:5156/maintenance-history). Разделы доступны через меню; главная страница — [localhost:5156](http://localhost:5156). Остановите приложение перед повторной сборкой, чтобы избежать блокировки исполняемого файла.

Для HTTPS сначала настройте доверие к сертификату разработки, затем запустите профиль:

```powershell
dotnet dev-certs https --trust
dotnet run --project EquipmentManager.csproj --launch-profile https
```

Адрес: [https://localhost:7128/equipment](https://localhost:7128/equipment). Порты заданы в `Properties/launchSettings.json`. Остановка приложения — `Ctrl+C`. База данных и внешние сервисы для текущего прототипа не требуются.

## Конфигурация и Git

`appsettings.json` и `appsettings.Development.json` содержат общие настройки журналирования и предназначены для репозитория. Не помещайте в них пароли, токены и строки подключения с учётными данными. `Properties/launchSettings.json` содержит общие локальные профили запуска и также сохраняется в Git.

Для локальных значений используйте переменные окружения или исключённые файлы `appsettings.Local.json` / `appsettings.*.Local.json`. Такие файлы автоматически приложением не загружаются: загрузку нужно отдельно реализовать при необходимости. Файлы `.env` также автоматически не читаются текущим приложением.

`.gitignore` исключает сборочные каталоги, настройки IDE, локальные конфигурации, `.env*`, файлы секретов, ключи и сертификаты. Исключения `.env.example` и `.env.sample` предназначены только для шаблонов без настоящих секретов. Документы лабораторных и `ui_concepts/` остаются доступными для добавления в Git.

Перед первым коммитом проверьте `git status --short` и содержимое `git diff --cached`. `.gitignore` не удаляет уже отслеживаемые файлы из индекса и не заменяет проверку содержимого на секреты.
