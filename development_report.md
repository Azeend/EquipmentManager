Дата составления: 16.10.2026. Технологии: C#, .NET 9, ASP.NET Core, Blazor Web App с InteractiveServer, Razor, Bootstrap и CSS.

## 2. Цель и ограничения

Развить учебный frontend от реестра оборудования до процесса «оборудование → заявка → выполненные работы → история», проверить его и провести безопасный рефакторинг.

Соблюдались AGENTS.md: существующая структура каталогов, PascalCase для типов и публичных свойств, camelCase для локальных переменных, nullable reference types, русские объяснения и XML-комментарии. Изменения ограничивались задачами; пароли и API-ключи не добавлялись. Дополнительные зависимости были разрешены пользователем только для тестирования. PostgreSQL, аутентификация и проверка ролей в этот этап не входили. Commit и push не выполнялись.

## 4. Компоненты и архитектура

| Файл / область | Назначение |
| --- | --- |
| Components/App.razor, Components/Routes.razor | Подключение стилей и Blazor, маршрутизация, InteractiveServer и фокус при навигации |
| Components/Layout/MainLayout.razor и .razor.css | Рабочая область, верхняя строка, переход к содержимому, ошибки и общие правила таблиц |

| Components/Pages/EquipmentList.razor | Реестр, поиск при вводе, формы создания/редактирования, подтверждение удаления, отмена и ошибки |
| Components/Pages/Faults.razor | Очередь, выбор оборудования, описание неисправности, начало и завершение работ |
| Components/Pages/MaintenanceHistory.razor | Фильтр оборудования, сортированная история, ссылки на заявки, пустота и ошибка с повтором |
| Models/Equipment.cs | Id, Name, InventoryNumber, Location, Status и допустимые состояния |
| Models/Fault.cs | Неизменяемый снимок заявки, версия, даты, работы и результат; модели форм с DataAnnotations |
| Models/MaintenanceRecord.cs | Неизменяемая связанная запись обслуживания |
| Services/EquipmentDataService.cs | Общий набор оборудования в памяти, копии данных, сохранение, уникальность и удаление под блокировкой |
| Services/FaultDataService.cs | Регистрация, разрешённые переходы, проверка версии и словарь истории по FaultId |
| Validators/EquipmentValidator.cs | Обязательные поля и допустимость состояния оборудования |
| EquipmentManager.Tests/ | Изолированные проверки валидатора, сервисов и настоящего фильтра компонента |

Сервисы зарегистрированы как singleton: данные общие для процесса приложения, а не постоянное хранилище. После перезапуска исходные демонстрационные данные создаются заново. Отмена оборудования безопасна за счёт отдельной копии редактируемой записи.

Разрешённая цепочка заявки: **Новая → В работе → Завершена**. Пропуск этапа, обратный или неизвестный переход отклоняются. Завершение проверяет описание работ и результат, сохраняет статус и запись истории под общей блокировкой. Ключ FaultId и проверка версии препятствуют повторным записям. Это гарантия текущего хранилища в памяти, а не PostgreSQL-транзакция. Дата истории соответствует времени завершения в UTC. Снимок названия оборудования сохраняет читаемость истории после переименования или удаления записи реестра.

## 7. Автоматическое тестирование

Создан EquipmentManager.Tests с net9.0. Использованы найденные в локальном NuGet-кэше версии: xunit 2.9.2, xunit.runner.visualstudio 2.8.2, Microsoft.NET.Test.Sdk 17.12.0. Допуск на тестовые зависимости был явно дан пользователем. Пакеты веб-приложения не менялись. В основном csproj исключены исходники и содержимое вложенного тестового проекта из сборки веб-приложения, проект добавлен в solution.

| Группа | Число выполненных тестов |
| --- | ---: |
| Пустые/пробельные Name, InventoryNumber, Location, Status | 8 |
| Корректное оборудование | 1 |
| Дублирующий номер, включая другой регистр и пробелы | 2 |
| Поиск по имени без учёта регистра и крайних пробелов | 2 |
| Запрет перехода Новая → Завершена | 1 |
| Завершение и повтор: одна связанная запись истории | 1 |
| **Всего** | **15** |

Тесты следуют Arrange–Act–Assert; сервисы создаются отдельно для каждого сценария. Поиск проверяется через существующее закрытое свойство компонента с reflection, без копирования алгоритма в тест. Это не браузерный рендеринг и зависит от имён закрытых членов.

Первый документированный прогон: 15 пройдено, 0 провалено, 0 пропущено; сборка с 4 предупреждениями NU1900. После аудита, исправления таблиц и шага 7: **dotnet build — 0 ошибок и 0 предупреждений; dotnet test — найдено 15, пройдено 15, провалено 0, пропущено 0**. Последние результаты взяты из frontend_refactoring.md и фактического вывода команд предыдущего шага.

Ранние разовые проверки сервисов также выполнялись во временных консольных программах: 16 проверок заявок и затем 19 проверок истории, включая 20 конкурентных попыток завершения с одним успехом. Это отдельные разовые проверки, а не дополнительные xUnit-тесты; к числу 15 они не прибавляются. Они не заменяют постоянную регрессионную инфраструктуру.

В отдельном процессе приложения с данными в памяти выполнены проверки Codex In-app Browser: 375×900, 768×900 и 1440×900 CSS px. Просмотрены снимки, измерены DOM-области, проверен клавиатурный ввод. Ниже приведены окончательные размеры после исправления таблиц из frontend_audit.md; более ранние значения до исправлений не смешиваются с ними.

| Страница | 375 px: контейнер / таблица | 768 px: контейнер / таблица | 1440 px: контейнер / таблица |

Во всех девяти измерениях документ был не шире viewport. Меню на мобильной ширине переносится вверх, формы вертикальны. Минимальные ширины таблиц: 56rem, 75rem, 64rem соответственно. На 375 px горизонтальная прокрутка истории клавишей ArrowRight изменила scrollLeft контейнера до 40 px при scrollLeft документа 0. Правые столбцы доступны прокруткой; частично видимая ячейка на границе области не означает обрезание её содержимого внутри таблицы.

Браузером также подтверждены ошибки пустой формы, запрет inv-1001 при существующем INV-1001, поиск без совпадений, отмена создания/удаления и фактическое удаление только временной записи ТЕСТ АУДИТА: число строк изменилось 5 → 6 → 5. Завершена тестовая заявка №2 и проверено появление истории. Исходные пять единиц оборудования не удалялись. После проверки процесс остановлен, тестовые изменения в памяти не сохранялись.

Клавиатурная проверка частичная: Enter, Tab, ввод, фокус подтверждения и горизонтальная прокрутка. Экранный диктор, все сочетания клавиш, несколько браузерных движков, потеря SignalR/circuit, имитация отказов источника и полная пустая очередь не проверялись. После рефакторинга шага 7 новый браузерный прогон не выполнялся; CSS и структура форм/таблиц на этом шаге не менялись.

## 9. Рефакторинг и производительность

В EquipmentList и MaintenanceHistory Count и foreach используют один отфильтрованный список текущего рендера. Для непустой выборки исключён второй проход Where/ToList; при ошибке истории фильтрация не запускается. Обработчики Faults развёрнуты на отдельные строки без изменения порядка операций.

Сохранены @key, стандартные обновления Blazor после событий и одноразовые флаги управления фокусом. Дублирующие формы не объединялись в общий компонент, поскольку их валидация и жизненный цикл различаются. ShouldRender, debounce, Virtualize, постоянный кэш и асинхронное хранилище не применялись: риски описаны в frontend_refactoring.md.

Количество рендеров не объявляется уменьшенным. Профилирование, измерения памяти, нагрузка 10 000/50 000 записей и p95 из ТЗ не выполнялись; численное ускорение не заявляется.

## 10. Локальный запуск и зависимости

Нужен .NET SDK 9.x либо совместимый SDK с установленными .NET Runtime 9 и ASP.NET Core Runtime 9. Целевая платформа обоих проектов — net9.0. Проверить окружение можно командами:

```powershell
dotnet --list-sdks
dotnet --list-runtimes
```

Из корня репозитория:

```powershell
dotnet restore EquipmentManager.sln
dotnet build EquipmentManager.sln --no-restore
dotnet test EquipmentManager.sln --no-build --no-restore
dotnet run --project EquipmentManager.csproj --launch-profile http
```

Адреса: [главная](http://localhost:5156/), [оборудование](http://localhost:5156/equipment), [заявки](http://localhost:5156/faults), [история](http://localhost:5156/maintenance-history). Остановка — Ctrl+C; перед повторной сборкой приложение следует остановить. Для восстановления пакетов нужен доступ к NuGet либо заполненный локальный кэш.

При необходимости HTTPS:

```powershell
dotnet dev-certs https --trust
dotnet run --project EquipmentManager.csproj --launch-profile https
```

HTTPS-адрес — https://localhost:7128; порты заданы в Properties/launchSettings.json. Эти команды являются инструкциями пользователю, а не заявлением о выполненной сейчас установке сертификата.

**Вместо package.json используется .csproj/NuGet.** EquipmentManager.csproj определяет SDK веб-приложения, net9.0 и свойства компиляции; EquipmentManager.Tests.csproj содержит PackageReference тестовых зависимостей. EquipmentManager.sln объединяет проекты. dotnet restore восстанавливает NuGet-зависимости, build собирает, test запускает тесты, run запускает приложение. Bootstrap уже находится в wwwroot, отдельная npm-сборка в текущем проекте не нужна. Эта адаптация методики соответствует стеку Blazor, а не пропуску настройки проекта.
