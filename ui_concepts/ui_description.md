# Концепции интерфейса EquipmentManager

Лабораторная работа №3. Все макеты самостоятельны: откройте любой HTML-файл в браузере. Сервер, интернет, установка пакетов и внешние библиотеки не нужны. Встроенные CSS и JavaScript находятся внутри каждого файла. Переходы между концепциями работают, если файлы расположены рядом.

Во всех вариантах представлены восемь единиц промышленного оборудования завода «Промтех»: станки, компрессор, кран, насос, пресс, сварочный аппарат и пила. Данные вымышленные. Поиск учитывает название, модель, инвентарный номер и расположение; фильтр статуса применяется совместно с поиском. Счётчик показывает число найденных записей. При отсутствии совпадений выводится пояснение. Статусы обозначены текстом и цветом. Загрузка — демонстрационный процент занятости оборудования за смену, а не показатель технической исправности.

## 1. Светлый минималистичный интерфейс

Файл: `concept_1_minimal.html`.

Особенности: тёплый светлый фон, крупная типографика, зелёный акцент, свободное пространство и компактная таблица. Навигация между концепциями вынесена в нижнюю часть страницы, чтобы основное внимание оставалось на реестре.

Преимущества:
- Низкая визуальная нагрузка, понятное начало работы.
- Хорошая читаемость названий, моделей и инвентарных номеров.
- Простая структура для небольшого парка оборудования.

Недостатки:
- Крупный вводный блок занимает часть полезной высоты экрана.
- Мало места для постоянной навигации при расширении приложения.
- Таблица на телефоне требует горизонтальной прокрутки.

## 2. Корпоративный интерфейс — основной вариант

Файл: `concept_2_corporate.html`.

Особенности: постоянное боковое меню, верхняя строка с контекстом предприятия и демонстрационным пользователем, сводные показатели, табличный реестр и блок обслуживания. Синий акцент, сдержанная палитра и плотная рабочая компоновка. Помимо статуса доступен фильтр подразделения. Пункты меню ведут к соответствующим блокам страницы. Кнопка «Открыть реестр» переводит к таблице.

Преимущества:
- Привычная организация рабочего места инженера и ответственного за учёт.
- Таблица позволяет сопоставлять активы сразу по нескольким признакам.
- Подразделения и состояния удобно комбинировать в фильтрах.
- Навигация подходит для будущих разделов заявок, ремонтов и отчётности.

Недостатки:
- Боковое меню уменьшает ширину рабочей области на ноутбуках.
- Интерфейс визуально плотнее минималистичного варианта.
- Для телефона меню перестраивается в верхнюю область, таблица прокручивается по горизонтали.

Выбор: концепция №2 наиболее подходит для дальнейшей разработки EquipmentManager на Blazor и .NET 9. Основная задача приложения — регулярный учёт оборудования, поэтому важны предсказуемая навигация, сравнение строк и фильтрация по подразделениям. Корпоративная компоновка сохраняет контекст предприятия и объединяет реестр со сводкой и очередью обслуживания. Её можно последовательно перенести в компоненты Blazor: оболочка с меню, панель фильтров, таблица, карточки показателей и блок обслуживания, сохраняя существующую структуру проекта. Для полноценного приложения потребуются реальные источники данных, авторизация и операции редактирования; макет их не реализует.

## 3. Тёмная панель мониторинга

Файл: `concept_3_dashboard.html`.

Особенности: тёмная тема, бирюзовый акцент, крупные показатели состояния парка, сетка карточек оборудования, полосы загрузки и отдельная лента событий смены. Показывается явно обозначенный демонстрационный срез, автоматического получения телеметрии нет. На узких экранах сетка переходит в одну колонку, события размещаются ниже оборудования.

Преимущества:
- Аварии и обслуживание легко выделить при обзорном контроле.
- Карточки удобны на телефоне и позволяют быстро оценить отдельный агрегат.
- События дают контекст изменения состояния.

Недостатки:
- Карточки занимают больше места, чем строки таблицы.
- Сравнение большого числа активов менее удобно.
- Тёмная тема может быть менее удобной при ярком освещении и печати.

## Адаптивность и доступность

Используются системные шрифты, гибкие сетки, медиазапросы, подписи полей для средств чтения с экрана, видимый фокус клавиатуры и текстовые обозначения статусов. Табличные области можно прокручивать с клавиатуры. Изменение числа результатов объявляется через `aria-live`. Анимация прокрутки отключается при соответствующем системном предпочтении. Сводные показатели всегда относятся ко всему демонстрационному парку; поиск и фильтры меняют только список и счётчик найденных записей.

## Границы макетов

Изменение и сохранение данных, экспорт, авторизация, серверные запросы и реальная телеметрия не входят в макеты. Данные сбрасываются при перезагрузке страницы. Существующие файлы Blazor-приложения не изменяются.
